# UI Audit Majordom — Visual, Attractive, and Functional Improvements

> **Date:** August 30, 2026 · **Method:** the application was started (full Docker stack: `majordom-web` on :3000, API, Actual Budget, Ollama), each page was opened in a headless browser at mobile viewport (390×844) and desktop (1440×900), with rendered DOM analysis (text, tap target sizes, overflow, SVG chart structure) + source code review of every page.
> **Scope:** report only — no files in the application were modified.
>
> *Note: Translated to English, originally written August 30, 2026 (same session as issues #231-240 were being worked).*

## What Is Already Good (Keep)

- **Coherent design system** — `PageHeader`, `IconButton`, `BottomSheet`, `AddButton`, `StandardHeaderActions` are shared; new pages can't drift visually.
- **Consistent dark theme** (Linear/Raycast palette), Syne + DM Mono fonts with `tabular-nums` on amounts — a good decision for financial data.
- **`aria-label` on all icon buttons** — better than most applications of this type.
- **True mobile‑first**: `pb-safe`/`pt-safe`, `dvh`, viewport `viewport-fit=cover`.
- **`WidgetLoading` separate from empty‑state** — "still loading" looks different from "there is nothing" (many applications confuse the two).
- **Unified AddButton** (Photo / CSV / Manual) in all headers.
- **BottomNav with 6 persistent tabs** + hidden on full‑screen flows.

## 1. Clearer Charts (Main Priority)

### 1.1 Chart Sizes
- `LineChart`: fixed viewBox `300×100` → on mobile it renders ~318×100px. **100px height is too little for a main trend chart.**
- `BarChart`: `MAX_BAR_HEIGHT = 80` → bars have a maximum of 80px, width `w-3` (12px). As a main chart it is weak.
- `Donut` (Chart.tsx): only **72px** with 8px stroke — more of an avatar than a chart. The donut in "Expenses Structure" (Dashboard) is 96px and has a total in the center; the one in Chat does not.
- **Recommendation:** line 160–200px height (×2 from current), bar 140–160px, donut 120–140px with total in center everywhere. The SVG is already scalable — only numbers need to be adjusted.

### 1.2 Axes and Labels (Biggest Clarity Gain)
- Line chart shows **only min/max** as Y values (`min 7,124.83 · max 67,064.27`), in 9px text, no gridlines, no units on the axis. It is not visible where the line passes through intermediate values.
- **Real clarity bug — X axis without year:** `formatDateShort()` omits the year. On the 12‑year vehicle projection (2024→2036), rendered labels are `29 Aug · 28 Aug · 27 Aug · 26 Aug` — points that are **one year apart** look like consecutive days. Guaranteed confusion.
  - Fix: if span > 1 year → `Aug '25`, `Aug '26`…; if span ≤ 45 days → `28 Aug`; deduplicate as now.
- Bar chart: the numeric value shown under each point is **only the first series** (`p.values[0]`) — the second series (e.g. income) has no visible values anywhere.
- **Recommendation:** 3–4 discrete horizontal gridlines + 3–4 Y labels with unit (€/km), intelligent X labels based on span, values for both series in the bar chart (or tooltip).

### 1.3 Interactivity — Zero Currently
- No tooltips, no reaction to tap/hold on points. Circles on the line chart have r=2.5 — impossible to hit precisely with a finger.
- **Recommendation:** tap on point/bar → floating tooltip with value + date; vertical crosshair on desktop hover; tap on bar in "spending vs income" → navigate to Transactions filtered for that month (drill‑down). The biggest functional leap for charts with medium effort.

### 1.4 Entry Animations
- Bars/progress bars have `transition-all duration-300/500` only on data changes. On first render the chart appears instantly, "flat".
- `framer-motion` is already in `package.json` (used in Import/Chat) — unused in charts.
- **Recommendation:** line = progressive drawing (`stroke-dashoffset`, 400ms), bars = grow from 0 with 30ms stagger, donut = rotate from 0. Plus "count‑up" (300–500ms) on large figures (€20,494, Net Worth) — immediate "premium" effect.

### 1.5 1‑Pixel Progress Bars (!)
- `GoalsSection` (FIRE + each goal) and `BudgetDashboard` (groups + subcategories) use **`h-px`** — a progress bar **1px tall** on a 390px screen. Practically invisible; a €7,200 goal looks identical to a €0 one.
- **Immediate fix:** `h-1.5`/`h-2` (6–8px) + visible background (`bg-border`, not `bg-border/40`). Effort: 4 lines of CSS.

### 1.6 Color Palette Is Fragmented in 4 Places
- `SEGMENT_COLORS` (Chart.tsx), `EXPENSE_COLORS` (Dashboard), `GROUP_COLORS` + dynamic HSL ramp `getBudgetColor` (BudgetDashboard), `GOAL_COLORS`, `INCOME_COLOR` — **the same category can have different colors on different widgets**, and the budget uses a green→red gradient that doesn't exist in the rest of the UI.
- **Recommendation:** a single centralized `category → color` registry (e.g. `lib/chartColors.ts`), inherited by all widgets; separate semantic color for states (over‑budget = `#FF2D2D`, already used).

### 1.7 "Dirty" Data Visible in Charts
- Balance trend shows `+833.9% vs 30d ago` (from €7,124 to €67,064) because the history includes incomplete snapshots / "Starting Balance"; Latest Transactions is full of `Unknown`. That's fine in test data, but the UI can help: a "partial data" label when the series has few points, and aggregation of system entries (`Starting Balance`, `Unknown`) under a single group.

### 1.8 Bar Chart Without Support for Negative Values
- `scaleHeight()` only handles values ≥ 0. If a "net cashflow" per‑month chart appears, negative values stay at `MIN_BAR_HEIGHT` (2px). Something to keep in mind if such charts are added.

## 2. Visual Improvements

### 2.1 Tap Targets Below 44px — The Most Widespread Problem
Actual measurements (viewport 390px):

| Element | Location | Current size |
|---|---|---|
| "New goal" (+) | Goals / Planned | **16×16** |
| "i" (InfoIcon) | next to each goal | **16×16** |
| "Edit groups" (pencil) | Categories Watchlist | **15×15** |
| ▼ expand group | Categories Watchlist | 16×24 |
| ‹ › month navigation | chart titles (Chart.tsx) | ~24×20 |
| 3M / 1Y / 5Y / All | vehicle charts | 28–30×19 |
| "Edit" / "Override value" | Vehicle Detail | 23–83×18 |
| row checkboxes | Transactions | **13×13** |
| "Add vehicle" | Accounts | 79×17 |
| List/Table toggles | Transactions | 65–74×28 |
| "Add" / Bell / Settings | headers (36px) | 36×36 |
| Send / + media | Chat | 40×40 |

- **General recommendation:** minimum 44×44px on mobile (`min-h-[44px] min-w-[44px]`, or extra padding on small elements — visually they can stay small, hit‑area not). Checkboxes in Transactions: the row is already `<label>` — if the visible tap area grows to 24px + full row hit‑area, selection becomes much more comfortable. ‹ › arrows in chart titles: `px-3 py-2` instead of `px-1`.

### 2.2 Typography Too Small
- Y‑axis labels: **9px**; many chart labels and badges: 10–11px. Below 11px on mobile is below comfortable readability threshold.
- **Recommendation:** minimum 11px for any informational text; 9–10px only for decorative text.

### 2.3 Contrast
- `muted-2 = #52525B` on `#0F0F0F` ≈ ratio **~2.5:1** — fails WCAG AA (needs ≥ 4.5:1 for small text). `muted = #71717A` ≈ 4:1 — borderline.
- **Recommendation:** raise `muted-2` to ~`#6B6B76` for text that conveys information ("target: Jul 2027", "est. 2037"), or keep it only decorative.

### 2.4 Skeleton Loading — Completely Absent
- `hasSkeleton: false` on all pages. Vehicle Detail and Account Detail return `<div className="min-h-dvh" />` **completely empty** while loading (black screen 1–3s). Dashboard has `WidgetLoading` (spinner + text — good), but no skeleton.
- **Recommendation:** card‑shaped skeletons (rounded blocks + `animate-pulse`) for each widget during fetch; `WidgetLoading` stays for re‑fetch. The most visible "before/after" in the entire report.

### 2.5 Header Not Sticky
- `PageHeader` scrolls with the content. On long pages (Transactions 4117px, Account Detail 3263px) you lose Add/Notifications/Settings immediately.
- **Recommendation:** `sticky top-0 bg-background/95 backdrop-blur z-40` on header.

### 2.6 Double Fixed Bar at the Bottom on Dashboard
- The "Customize + Current month" bar (fixed, `bottom-16`) + BottomNav = two fixed layers; content is compensated with `pb-36`. On a normal phone, ~140px of viewport is fixed chrome.
- **Recommendation:** a single layer — period controls moved to the header (next to Add/Bell/Settings or below the title), or period bar shown only on scroll‑up (iOS "mini header" model).

### 2.7 Desktop = Stretched Mobile
- At 1440px, Dashboard uses a 2‑column grid (`sm:grid-cols-[1.15fr_1fr]`) — good — but without `max-w` container: on a large monitor widgets stretch excessively; Transactions/Account Detail become ~1400px‑wide rows, illegible.
- **Recommendation:** `max-w-[1100px] mx-auto` on the page wrapper + for Transactions a desktop table layout with columns (date/merchant/category/account/amount — already exists in the table view).

### 2.8 Polish Details
- "Portfolio Independence**i**" — the InfoIcon "i" appears glued to the goal name (in rendered text it really is glued); spacing + more visible icon.
- Account Detail: tab pills (Details/Transactions) are 25px tall with 11px text — small; worth `min-h-[36px]`.
- Goals with negative percentage (crypto.com −23%) — make sure the negative is visually emphasized (red/gray), not just the minus sign.
- Dates in 3 different locales in the UI: `en-GB` (Dashboard header), `en-NL` (Transactions list), `nl-NL` (Vehicle) + nl-NL numbers. Unify to a single locale.

## 3. Attractiveness (Micro‑interactions & Delight)

1. **Count‑up on large sums** — Today / Net Worth / Current value: 500ms animation from previous value to new one. Cheap, makes the app feel "alive."
2. **Haptic feedback** (`navigator.vibrate(10)`) on: confirming a proposal from Chat, bulk‑apply in Transactions, saving a goal. The PWA gains native feel on Android.
3. **Pull‑to‑refresh** on Dashboard/Transactions — currently refresh is only implicit (staleTime).
4. **Empty states with personality** — "Coming soon" / "No vehicles yet" are bare text. Small icon + a sentence in the assistant's tone ("Nothing to review 🎉") + CTA where it makes sense.
5. **Celebration on save** — ReceiptFlow already has a dedicated SuccessScreen (very good!) — add an animated check (scale+spring) and subtle confetti on Chat confirmations.
6. **Transitions on month change** — on ‹ › on Dashboard, widgets jump abruptly; `AnimatePresence` with fade/slide 150ms on each card = feeling of fluidity.
7. **"Live" chart** — a small pulse on the last point of the line (circle with `animate-ping`) on Balance trend communicates "live data."

## 4. Functional Improvements

### 4.1 Analytics — a Whole Tab Is Placeholder
- "Reports — coming soon" occupies one of the six tabs. The page has a natural entry point: move here the charts that already exist in the backend (`finance_charts.py`, vehicle charts): monthly trends, income vs expenses, top categories, savings rate. Alternatively, hide the tab until it has content.

### 4.2 Vehicle Detail — 404 Waits 15s on Empty Screen
- With a wrong `vehicleId` (old link / bookmark), `QueryClient` retries 4× (1+2+4+8s) → **~15s of completely black screen** before "Vehicle not found." `getVehicle` does not set `retry: false` (only `projectionQuery` has it).
- Fix: `retry: false` + `refetchInterval: false` on `vehicleQuery` as well (a 404 response is permanent, not transient) + skeleton while the 6 charts load (currently they appear sequentially, without any indicator).

### 4.3 Chat — Raw Technical Errors Visible
- In real history: `Tool error: set_account_goal() missing 1 required positional argument: 'target'`. The user sees Python exception messages.
- Recommendation: map tool errors → friendly message ("I couldn't set the goal — want to try again?") + technical detail inside a "Details" disclosure.

### 4.4 Settings — Dead Rows + Phantom Settings
- `InertRow` "Not built" for: Light/System theme, Change password, Run backup now, Restore from backup, Default account, MCP server — looks almost identical to real settings (only the subtitle differs). User taps and nothing happens → frustration.
- **`GeneralPage`: toggles "Include credit limits" / "Show archived accounts" are just local `useState` — not saved anywhere and don't affect anything.** Phantom settings.
- Recommendation: rows marked "Not built" visually degraded (dashed border + "planned" chip), and non‑functional toggles removed until they have a backend.

### 4.5 Transactions
- **Raw ISO date in the Table view** (`2026-08-30`) vs list view formatted (`30 Aug`) — inconsistent.
- **No sticky table header** on long scroll (4117px); no grouping by day/month (header "August 30 · 5 transactions").
- "Load more" button — infinite scroll with `IntersectionObserver` would eliminate a tap every 50 rows.
- Checkbox is permanently visible — a separate selection mode (a "Select" button in the header) would clean up the visual navigation of the list.
- No CSV export of the filtered view — very useful at month end.

### 4.6 Account Detail
- Flat list of 50 transactions, without: grouping by date, monthly summary (in/out/net), balance sparkline, search. The page is 3263px of identical rows.
- Minimum recommendation: sticky date separators + a small summary at the top (current month: +in / −out).

### 4.7 Accounts
- "Add vehicle" 79×17px — flimsy link for an important action.
- Account rows do not show the type (Vehicle/Loan/Investment) — all have the same `Wallet` icon, even though `account_type` exists in the API.
- Vehicle rows without a match in vehicle‑manager are `disabled` + `opacity-60` **with no explanation** — a "not linked" badge would clarify why they cannot be tapped.

### 4.8 Code Cleanup
- `components/TransactionItem.tsx` is no longer used anywhere (Dashboard renders its own rows) and has a broken emoji map anyway: `CATEGORY_EMOJI` has slug keys (`groceries`), but `tx.category_id` is a UUID → **it would always show 📦**. Delete it, or fix it with `tx.category` (the name) as the key if the component is revived.

### 4.9 PWA
- Manifest: `orientation: "portrait"` blocks landscape on tablets; icons are not `maskable` (ugly crop on Android); no `shortcuts` (e.g. "Scan receipt" from long‑press — perfect for the photo flow); no `screenshots` for a richer install prompt.

### 4.10 Chart Accessibility
- SVG elements in charts lack `role="img"` / `aria-label`. An `aria-label` generated from the title + min/max (e.g. "Balance trend, August: from €7,124 to €67,064") is cheap and sufficient for a screen reader.

## 5. Proposed Prioritization

### Quick Wins (≤ 1 hour each, high impact)
1. **Fix X axis with year** on line chart (the "29 Aug 28 Aug 27 Aug" bug on vehicle projection) — Chart.tsx, label formatting.
2. **Progress bars `h-px` → `h-1.5`/`h-2`** in GoalsSection + BudgetDashboard (4 CSS classes).
3. **44px tap targets** on: ‹ › month, InfoIcon, New goal, expand group, 3M/1Y/5Y/All.
4. **Labels 9–10px → 11–12px** on axes and badges.
5. **`retry: false` on vehicleQuery** — eliminates the 15s black screen.
6. **Hide raw errors from Chat** behind a friendly message.
7. **ISO date formatted** in Transactions table view.

### Medium Effort (½–2 days)
8. Chart height ×1.6–2 (line 160px, bar 140px, donut 120px+) + Y gridlines + units.
9. **Tooltip on tap on points/bars** (+ drill‑down to filtered Transactions from bar chart).
10. Loading skeletons for all widgets + Vehicle/Account Detail.
11. Entry animations on charts + count‑up on sums + fade on month change.
12. Unify the category color palette into a single registry.
13. Sticky header (page) + sticky date headers (Transactions).
14. Grouping by date + monthly summary in Account Detail.
15. Distinct icon per account type in Accounts + "not linked" badge on vehicles.
16. Settings: "Not built" rows visually degraded, phantom toggles removed.
17. PWA: maskable icons + shortcuts.

### Larger Projects
18. **Real Analytics page** — reusing existing chart endpoints + drill‑down.
19. Desktop layout with `max-w` container + native table view on monitor.
20. Pull‑to‑refresh + haptics + infinite scroll ("native app" interaction model).
21. Dashboard: move the period bar from the fixed bottom layer to the header (recovers ~70px of viewport).
