### Lessons
- **Correction to an earlier note in this same entry:** project-level subagents (`.claude/agents/*.md`) do *not* require a fresh Claude Code session to become callable, as first assumed after the immediate `Agent type 'pre-commit-review' not found` error. It showed up in the available-agents list later in this same session (confirmed via a later system reminder), just not instantly like a newly-written skill. Exact refresh trigger unverified — don't claim "needs a new session" as fact; if an immediate invocation fails, wait and retry within the session before concluding it's unavailable.
- When extracting a section that other live docs cross-reference by anchor (`CLAUDE.md#priority-tracking`), grep for the anchor across the whole repo *before* moving it, and update the live references (this repo already learned this lesson once, for `architecture.md` rules 18-19 — see "Known process gaps" #3 — but that time chose to tag-in-place instead of physically move; this time physically moving was the whole point, so the fix was updating the ~5 live cross-references instead).

- **A rule whose whole point is hiding X can't live in a place that itself reveals X.** Moving the commit-timestamp rule from global auto-memory into `CLAUDE.md` fixed the "no auto-memory" violation but created a worse one — a tracked, public file explaining exactly how and why timestamps are faked, with a real example. `CLAUDE.local.md` (gitignored) is the correct home for a rule that must never be visible, not the project's main tracked instructions file. - **Quoting content across a language boundary needs translation, not just quoting.** Pulling section/field names from the vault's Romanian-language templates directly into this (English-only) repo's session log carried the Romanian text over verbatim without noticing — describing something Romanian doesn't require quoting it in the original language.
- **`echo "$var" | grep -P` with multi-byte UTF-8 is unreliable in this environment in more than one way, not just the false-negative already documented above (2026-07-07).** Tonight it also produced an outright `grep: character code point value in \x{} or \o{} is too large` error specifically with PCRE `\x{...}` code-point escapes — intermittent, not reproducible on demand, and silently swallowed by the script's `|| true`, so the check just silently didn't fire. Switching to literal UTF-8 characters in the pattern (no escapes) was reliable across every retest. If a check ever needs to match specific Unicode characters again, prefer literal characters over `\x{...}` escapes in this environment, and test the positive-match case repeatedly (not just once) before trusting it.
- A vault-based Agent Skill (`progres-claude-code`) can miss a session that hits its own trigger criteria squarely — auto-trigger reliability isn't just a Majordom-internal concern, it applies to the meta-layer of skills-about-sessions too. Now has an explicit-invocation fallback documented in the skill itself.
