### Lessons
- **A CSS bug chased across 3 iterations before the fix was "make it structurally impossible to fail," not "patch the specific case."** A bottom sheet kept clipping/misplacing itself at narrow widths — root cause was `position:absolute` resolving against a *scrolling* ancestor (so a sheet opened after scrolling down rendered above the fold) layered with a separate "floating centered card" CSS variant whose `calc()`/`max-width` math kept producing edge cases. - **Flex/grid children default to `min-width: auto`, not `0`** — a flex row (`.catrow`, `.gran-tabs`) or grid track can force its container wider than intended when content can't shrink below its own min-content size, even with `overflow-x: auto` set on a sibling. `min-width: 0` on the shrinking item is the fix; this bit the same mockup twice before the pattern was recognized.

When re-applying an old decision to a new question, check whether the old decision's actual scope covers the new question, not just its general vibe.
