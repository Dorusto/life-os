### Lessons
- **Check `temperature` first on any future report shaped like "the LLM ignored a clear instruction."** It reproduces exactly like a flaky-prompt bug (same input, different outcome each time) and is far cheaper to rule out than writing a new bullet or building a forced-`tool_choice`/retry mechanism. `backend/api/chat.py` was the only LLM call in the whole codebase with no `temperature` set — every other one (vision, CSV detection, notifications) sets it explicitly.
- **Don't trust a single live trial.** The first uncategorized-transactions test (pre-fix) looked like a clean pass at first glance in one run and a total fabrication in the next, same phrasing, fresh chat each time — a single test would have reported "fixed" wrongly in either direction. 3 fresh trials was the minimum to see the real pattern (and to later confirm the fix).
- **Closing an issue on "the code now matches the fix I applied" isn't the same as closing it on "the issue's actual ask is done."** #243 asked for a mechanical check; closed it because the 9 bullets it *found* were fixed, without re-reading that the check itself — the actual deliverable — was still unbuilt. Caught immediately, reopened same session, no real harm, but worth remembering: re-read the original ask right before closing, not just what got fixed.
- Pre-commit review caught a real mistake before it shipped: a new example bullet I wrote copied a real vehicle nickname ("Wabi Sabi") from a pre-existing example elsewhere in the same file, instead of the established fictional placeholder (`MyCar`/`MyBike`) — architecture.md rule 21 (`docs/architecture.md` "never use real user data as few-shot examples"), same category as the original #139 incident. Fixed before commit. The pre-existing occurrence (not part of this diff) is now tracked in #244.
