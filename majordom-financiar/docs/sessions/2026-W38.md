## 2026-09-15 — #295: notification bell popup clipped at top (BottomSheet vs PageHeader backdrop-blur)

### Resolved

- Root cause confirmed and fixed: `PageHeader`'s `backdrop-blur` makes the sticky header the CSS containing block for `position: fixed` descendants, so `BottomSheet`'s `fixed inset-0` overlay (rendered inside the header via `StandardHeaderActions`) resolved against the ~90px header box instead of the viewport — panel clipped at the top, no visible backdrop. Fix is one file, +7/−2: `BottomSheet.tsx` renders its overlay through `createPortal(..., document.body)`, escaping any transformed/filtered ancestor for every BottomSheet consumer at once. Implemented by opencode-61's `senior` agent (DeepSeek V4.1 Flash) on `fix/notification-bell-sheet-clipped`, independently reviewed by a fresh `senior` instance via `review-diff.sh` (PASS), and live-verified end-to-end on a real no-Docker local stack on opencode-61 (vite + uvicorn + `npx @actual-app/sync-server` with a fictional budget seeded via actualpy): login → dashboard → bell popup full-card at the bottom, mobile viewport 390x844. Merged fast-forward to local `main` (`3e8ca6f`).
- Push to `origin` blocked from opencode-61 (no write credentials — HTTPS 403; consistent with the W38-evening deploy-key revocation). Doru pushes `main` from the machine with rights — it carries `22bd867` (get_net_worth_history) plus `3e8ca6f`; #295 closes after that push.

- `backdrop-filter` (like `transform`/`filter`) silently becomes the containing block for `position: fixed` descendants — promoted to `architecture.md` rule 44. Future fixed overlays must portal to `document.body`.
- opencode-61 can host a full no-Docker test stack: uvicorn backend + vite dev frontend (from the fix worktree) + `npx @actual-app/sync-server` (config JSON with explicit `serverFiles`/`userFiles` — env `ACTUAL_PASSWORD` does not exist on the sync-server package; password set via its own bootstrap API) + fictional AB data via actualpy (`create_budget()` → populate session → `commit()` → `upload_budget()`); app login users come from `USER1_*` env vars, AB connection via the wizard's encrypted store.
